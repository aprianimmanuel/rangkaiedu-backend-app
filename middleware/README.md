# Middleware

This directory contains all the middleware functions for the Rangkai Edu backend.

## Authentication Middleware

The authentication middleware provides JWT token validation and user context management for protected routes.

### Files

- `auth.go` - Main authentication middleware implementation
- `roles.go` - Role-based authorization functions

## Usage

### Basic Authentication

To protect a route with JWT authentication, use the `AuthRequired` middleware:

```go
import (
    "github.com/gin-gonic/gin"
    "github.com/aprianimmanuel/rangkaiedu-backend-app/middleware"
)

func SetupRoutes(r *gin.Engine) {
    // Protected route group
    protected := r.Group("/api")
    protected.Use(middleware.AuthRequired())
    {
        protected.GET("/profile", ProfileHandler)
    }
}
```

### Role-Based Authorization

To protect a route with role-based authorization, use the `RoleRequired` or `RolesRequired` middleware:

```go
import (
    "github.com/gin-gonic/gin"
    "github.com/aprianimmanuel/rangkaiedu-backend-app/middleware"
)

func SetupRoutes(r *gin.Engine) {
    // Admin-only routes
    admin := r.Group("/api/admin")
    admin.Use(middleware.AuthRequired())
    admin.Use(middleware.RoleRequired(middleware.RoleAdmin))
    {
        admin.POST("/users", CreateUserHandler)
    }

    // Multiple roles allowed
    content := r.Group("/api/content")
    content.Use(middleware.AuthRequired())
    content.Use(middleware.RolesRequired(middleware.RoleAdmin, middleware.RoleTeacher))
    {
        content.POST("/lessons", CreateLessonHandler)
    }
}
```

### Accessing User Context

In your handlers, you can access the authenticated user's information:

```go
func ProfileHandler(c *gin.Context) {
    // Get user from context
    userInterface, exists := c.Get("user")
    if !exists {
        c.JSON(http.StatusUnauthorized, gin.H{"error": "User not found in context"})
        return
    }

    // Type assert to UserContext
    user, ok := userInterface.(middleware.UserContext)
    if !ok {
        c.JSON(http.StatusInternalServerError, gin.H{"error": "Invalid user context"})
        return
    }

    // Use user information
    c.JSON(http.StatusOK, gin.H{
        "id":    user.ID,
        "email": user.Email,
        "phone": user.Phone,
        "role":  user.Role,
    })
}
```

## User Context Structure

The `UserContext` struct contains the following fields:

```go
type UserContext struct {
    ID    string `json:"id"`
    Email string `json:"email"`
    Phone string `json:"phone"`
    Role  string `json:"role"`
}
```

## Role Constants

The following role constants are defined:

```go
const (
    RoleAdmin    Role = "admin"
    RoleTeacher  Role = "teacher"
    RoleStudent  Role = "student"
)
```

## Error Responses

The middleware will return the following HTTP status codes and error messages:

- `401 Unauthorized` - When a token is missing, invalid, or expired
- `403 Forbidden` - When a user doesn't have the required role for a route

## Testing

This directory contains comprehensive tests for the middleware functions. The tests are written using Go's built-in testing framework and follow the same patterns as the rest of the project.

### Test Files

- `auth_test.go` - Tests for the AuthRequired middleware
- `roles_test.go` - Tests for the RoleRequired and RolesRequired middleware
- `integration_test.go` - Integration tests with the existing authentication system

### Running Tests

To run all middleware tests, use the following command from the project root:

```bash
go test ./middleware
```

To run tests with verbose output:

```bash
go test -v ./middleware
```

To run all tests in the project:

```bash
go test ./...
```

### Test Coverage

The tests cover the following scenarios:

1. AuthRequired middleware:
   - Valid token authentication
   - Missing token handling
   - Invalid token handling
   - Expired token handling

2. RoleRequired middleware:
   - Valid role authorization
   - Invalid role handling

3. RolesRequired middleware:
   - Valid role authorization (multiple allowed roles)
   - Invalid role handling

4. Integration with existing authentication system:
   - Tokens generated by the existing auth system work with our middleware
   - User context is properly stored and accessible
   - Role-based access control works correctly
